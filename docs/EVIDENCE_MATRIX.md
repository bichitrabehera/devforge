# Evidence matrix — Track 4 "Trust, but verify"

Every row: the public demonstration to run, the expected behavior **defined
before the run**, the actual result with its status, and the limit stated in
the same row. Statuses: `measured` (run and reproduced locally, commands
included), `partial` (works, documented boundary), `not supported`.

| # | Goal | Public demonstration | Expected behavior | Result / status | Limit |
|---|------|----------------------|-------------------|-----------------|-------|
| 1 | Key rotation | `python3 demo.py` (rotation step) or `{"op":"rotate_key"}` → `{"op":"authenticate","key_version":old}` before and after `cutoff_at` (advance clock via `advance_time`) | New version served immediately; old version accepted inside the documented grace window, rejected after `cutoff_at`; grace length reported in every response (`grace_seconds`, default 30 s) | **measured** — `tests/test_objectives.py::TestRotationCutoff` (4 tests), `tests/test_selfattack.py` item 5; grace accepted / cutoff denied shown in `docs/performance_metrics.json` (`grace_period`) | Simulated clock in embedded mode; real clocks in `demo_networked.py` |
| 2 | Revocation across nodes | `{"op":"revoke","actor":X}` → response carries per-node `enforcement_times`; verify each node: `{"op":"authenticate","node":"node-b"}` | Revoked actor denied at every node at `revoked_at + node.sync_delay_s` (node-a 0 s, node-b 2 s, node-c 4 s); bystanders unaffected; owner can `re_enroll` | **measured** — `tests/test_objectives.py::TestRevocationAcrossNodes`; networked variant: 3 real node processes, measured propagation in `docs/demo_networked_output.json` | Embedded sync delays are configured constants; networked mode uses real polling eventual consistency |
| 3 | Crash recovery | `rotate_key` → `crash_rotation` → `recover_state` → reads still work; then `revoke` + `kill -9` a mid-flight process (`tools/selfattack.py` item 7) → read again | After interrupted rotation the committed version is authoritative; revoked keys stay revoked; protected data available | **measured** — `tests/test_objectives.py::TestCrashRecovery`, `tests/test_gap_closure.py::EmbeddedRecoveryTest`, selfattack item 7 | Crash is process-kill simulation, not power loss; state file atomicity (fsync+replace) is the guarantee |
| 4 | Backup integrity | `create_backup` → `damage_backup` → `restore_backup` must refuse; clean backup restores; independent check: `python3 verifier/track4_verify.py backup --file backups/ID.json --pub <pk>` | Restore uses ONLY verified material; damaged payload → error, no restore; verifier exit 0 on clean, 1 on damaged | **measured** — `tests/test_objectives.py::TestBackupIntegrity`, `tests/test_adversarial.py::TestBackupSwap`, `tests/test_verifier.py::test_backup_verification` | Backup storage is signed, not encrypted at rest; access control on backup files is assumed |
| 5 | Log integrity | `tamper_log seq=1` → `verify_log` → `{valid:false, first_bad_seq:1}`; injections via `append_log` with newline/JSON/unicode payloads; independent: `python3 verifier/track4_verify.py audit --state state.json --pub <pk> --expect-head <head>` | Each event keeps original identity/action/record boundary; user text can never forge a second event or change the recorded actor; verifier agrees independently (exit 0 clean / 1 tampered / 2 unverified completeness) | **measured** — `tests/test_objectives.py::TestLogIntegrity`, `tests/test_qa_gapfill.py::TestLogChainMutations`, `tests/test_objectives.py::test_injection_text_stays_one_record`, `tests/test_verifier.py` (8 tests), `tests/test_kat.py` cross-implementation | Log integrity assumes the ML-DSA service key is not exposed; verifier needs the public key out of band |
| 6 | Routine vs suspicious activity | `python3 scripts/eval_detector.py --events practice/... --title practice --out docs/metrics/practice.json` | Approved administration separated from unexpected privilege changes; report F1, median TTA, false alerts/1000 | **measured** — practice: F1 1.000, TTA 1.2 s, 0 FP/1000; held-out 12,000 events: F1 0.748, P 0.999, 0.1 FP/1000 (`docs/DETECTOR_METRICS.md`) | Rules tuned on the 22 practice events; held-out recall bounded by the documented routine_denial trade-off |
| 7 | Lateral movement | Same evaluation; `evaluate_live` over the service's own audit log | Unusual service paths flagged even with valid credentials; each alert names identity, services, events and rule | **measured** — held-out lateral F1 0.609 (P 0.995, R 0.439), alert carries rule/identity/services/related events/explanation | Deny-heavy probes after an effective revocation are excluded from bursts (documented trade-off) |
| 8 | Clock differences | Events with `source_clock_offset_ms` within ±60,000 and beyond; arrival inversions within/over the 10 s tolerance | Offsets removed before ordering; beyond ±60 s flagged `order_uncertain`; inversions ≤ 10 s annotated `delayed_delivery` | **measured** — `tests/test_objectives.py::TestDetectorLabelled` (offset cases), `tests/test_adversarial.py::TestDetectorPoisoning`; held-out includes 2,585 offset events + 769 delayed deliveries | Beyond ±60 s order cannot be trusted (flagged, not silently ordered) |
| 9 | Replay & recipient binding | `message_send` → deliver → re-deliver same envelope; deliver to wrong recipient; flip one ciphertext byte; rename `msg_id` | Duplicates rejected (`duplicate_replay`), wrong recipient rejected (`recipient_binding_mismatch`), tampered ciphertext rejected, renamed metadata rejected | **measured** — `tests/test_objectives.py::TestMessaging`, `tests/test_qa_gapfill.py::TestMsgIdBinding`, `tests/test_adversarial.py::TestMessagingAttacks`, selfattack item 12 | msg_id is derived metadata (sha256(sid|counter)); the AEAD binds sid/sender/recipient/counter/context/key_version |
| 10 | Forward secrecy | Establish session, send, `session_close`, then give the attacker every secret now on disk (identities, service key, key versions) and try each against the captured ciphertext — selfattack item 13 does exactly this | No long-term secret decrypts captured traffic; session key and ephemeral secret zeroized on close | **measured** — `TestForwardSecrecyCompromise` (worst-case brute over every persisted secret), selfattack item 13 | Resumption secret persists until next resume (documented); live-memory disclosure of a running process is out of scope |
| 11 | Delivery under loss or reordering | Send m1..m3, deliver in order 3,2,1 (`tests/test_networked.py` reorder scenario); drop a message beyond the window | In-window reorders buffered and delivered in counter order when the hole fills; beyond-window gaps rejected with a reported delivery failure (`inbox_drain`) | **measured** — networked reorder/loss integration tests across REAL processes | Window is fixed at 8 counters (documented); receiver is a separate process with RAM-only keys |
| 12 | Session resumption | `session_close` → resume with the issued token for the right peer; resume attempt by a DIFFERENT identity with the same sid and the stolen token | Resumed session stays bound to its authenticated peer; wrong peer rejected (`peer_not_bound_to_session`); each resume ratchets the key | **measured** — `tests/test_objectives.py::TestMessaging` (resumption), networked resume-sub-mismatch scenario | Resumption secret exposure breaks future resumptions of that session only (documented) |
